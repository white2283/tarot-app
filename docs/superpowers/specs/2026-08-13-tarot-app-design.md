## 1. 背景与目标

一个塔罗牌占卜 Web 应用,核心功能:**牌阵选择 → 洗牌抽牌 → 翻牌揭示 → 解析解读 → 历史记录**;第二阶段加入**神谕卡**模块(每日一抽场景)。

- 第一阶段交付:本地可开发、可构建的全栈 Web 应用
- 部署目标:owner 的 Linux 云服务器,**公网访问**,分享给朋友使用
- 远期可能扩展为小程序 / App,因此后端 API 必须是平台无关的 REST 接口,前端只是其中一个客户端

## 2. 关键决策(已与 owner 确认)

| 决策点 | 结论 |
| --- | --- |
| 产品形态 | 本地开发的 Web 应用,部署到公网 Linux 云服务器 |
| 解析引擎 | **混合模式**:本地模板文案打底(必出结果),AI 深度解读为可选增强层,失败自动回退 |
| 牌面视觉 | **符号化牌面**:每张牌一个专属符号场景,SVG 实时渲染,无图片资源;风格以 `tarot-preview/` 样张为准 |
| 后端 | 必须存在(公网部署):代理 AI 请求保护 Key、缓存解读、存储历史记录 |
| 访客体系 | 访问口令 + 匿名访客 ID,不做注册登录账号系统 |
| AI 接口 | OpenAI 兼容格式(默认 Moonshot/Kimi),Key 仅存服务器 `.env` |
| 牌阵清单 | **7 个**(见 4.2),定义以参考资料《牌阵合集》为准 |
| 分领域牌义 | 每张牌带 `domains` 字段(至少 general + love),模板层按问题领域选文案 |
| 神谕卡 | 纳入**第二阶段**:通用 Deck 数据模型,首发"月相神谕卡" |

## 3. 技术栈

- **前端**:React 19 + TypeScript + Vite + Tailwind CSS v3 + Framer Motion(洗牌/翻牌动画)
- **后端**:Node.js(>=20.19)+ Fastify + better-sqlite3(SQLite 单文件,零配置)
- **测试**:Vitest(core 单测 + API 集成测试)
- **部署**:`npm run build` 产物由 Fastify 直接伺服静态文件;pm2 守护进程;`.env` 管理口令与 Key;预留 nginx 反代 + HTTPS 位置

## 4. 数据结构设计

### 4.1 牌库 `cards.json`(78 张,韦特系)

```json
{
  "id": "major-00",
  "name": "愚人",
  "nameEn": "The Fool",
  "arcana": "major",
  "number": 0,
  "suit": null,
  "keywords": ["开始", "自由", "冒险"],
  "upright": "正位解读文案…",
  "reversed": "逆位解读文案…",
  "domains": {
    "general": "通用场景下的侧重解读…",
    "love": "爱情问题下的侧重解读…"
  },
  "symbols": [
    { "type": "sun", "x": 70, "y": 15 },
    { "type": "cliff", "x": 50, "y": 80 },
    { "type": "dog", "x": 60, "y": 70 }
  ],
  "palette": { "bg": "#1a1030", "fg": "#e8c96a" }
}
```

- 22 张大阿尔卡那(`arcana: "major"`, `suit: null`)+ 56 张小阿尔卡那(`arcana: "minor"`, `suit`: `wands | cups | swords | pentacles`,数字 1–10 + 侍从/骑士/王后/国王)
- `domains`:分领域牌义(general 必填,love 等其余领域可选);模板引擎按用户问题的领域优先取匹配文案,无匹配则回退 general。结构依据参考资料《其实你已经很塔罗了》的"大体意义/两性关系意义/逆位"分段方式
- `symbols`:每张牌专属的符号场景,元素类型 + 相对坐标,由 `CardFace` 组件渲染为 SVG 组合;符号类型枚举在实现时定义为有限集合(sun/moon/cliff/tower/chalice/lightning 等),逐牌从牌面描述提取 2–4 个关键意象
- **牌义文案来源与版权处理**:正/逆位文案以《无边框韦特说明书》(自带正逆位三段式)为骨架,《塔罗逆位精解》丰富逆位层次,《穆夏塔罗说明书》补充意象与关键词;所有文案**改写润色后使用**,不照抄原文(资料标注"翻译仅供参考"且有机翻错误);符号意象依据韦特/穆夏说明书的牌面描述提取

### 4.3 神谕卡(第二阶段)

- **通用 Deck 模型**:塔罗与神谕卡共用同一套 Deck 抽象——`{ id, name, type: "tarot" | "oracle", cards: [...] }`;神谕卡条目 `arcana: "oracle"`,**无逆位**(`reversed` 字段缺省即不出现逆位),张数不定(30~50)

## 6. 前端核心模块(纯 TypeScript,无 UI 依赖,可单测)

### 6.1 `core/deck.ts`

- `createDeck(deckData): Card[]` — 从牌组数据构建牌堆
- `shuffle(deck, rng?)` — Fisher-Yates,可注入随机源便于测试
- `draw(deck, count): DrawnCard[]` — 从剩余牌堆抽取,**不重复**;塔罗牌每张含 `reversed: boolean`(正/逆位各 50%),神谕卡不产生逆位

### 6.2 `core/interpret.ts`

- 接口 `Interpreter`:输入(问题、牌阵、抽到的牌及位置),输出结构化解读(整体叙事 + 逐位解读)
- `TemplateInterpreter`:位置含义 × 牌义(按问题领域选 `domains` 文案)× 正逆位 → 模板组合;**离线必出结果**
- `AIInterpreter`:调用后端 `/api/interpret`;**超时(10s)/错误/未配置时自动回退 TemplateInterpreter**,UI 标注"基础解读"

### 6.3 `core/session.ts`

一次占卜的状态机:`selectDeck → selectSpread → askQuestion → shuffle → draw → reveal(逐张翻牌)→ interpret → save`,前端路由与动画由状态驱动。

## 7. 页面流程(4 个主视图 + 1 个历史记录页)

1. **首页**:牌组(塔罗/神谕卡)与牌阵卡片列表;首次进入要求输入访问口令(后端校验,token 存 localStorage)
2. **抽牌页**:输入问题(可选领域标签:综合/爱情)→ 洗牌动画 → 牌背扇形铺开 → 用户逐张点选
3. **翻牌页**:按牌阵布局摆放,点击触发 3D 翻转动画,揭示符号场景牌面
4. **解析页**:逐位解读(牌名 + 正/逆位 + 位置含义 + 文案)+ "✨ AI 深度解读"按钮 + 保存到历史
5. **历史记录页**:从首页进入,按时间倒序列出本人过往解读,可点击查看详情

## 8. 后端 API

| 接口 | 说明 |
| --- | --- |
| `POST /api/auth` | 校验访问口令(`.env` 配置),签发访客 token(含匿名访客 ID);朋友各自独立,无需注册 |
| `POST /api/interpret` | AI 解读代理;入参:问题 + 牌组 + 牌阵 + 抽到的牌;缓存键 = 四者哈希,命中缓存零 token 消耗;**每访客每天限 20 次**,超限回退模板解读 |
| `GET /api/history` | 按访客 token 读取本人历史 |
| `POST /api/history` | 保存一条解读记录 |

- 除静态资源与 `/api/auth` 外,所有接口需携带有效访客 token
- AI 请求由后端发往 OpenAI 兼容端点,Key 仅存 `.env`,绝不下发前端

## 9. 错误处理与降级

- AI 超时 10 秒 / HTTP 错误 / 未配置 Key → 静默回退模板解读,UI 标注"基础解读"
- 限流触发 → 提示当日 AI 次数已用完,仍展示模板解读
- 断网 → 模板解析照常可用(牌库/牌阵/文案全在前端打包);历史与 AI 功能不可用并明确提示
- 口令错误 → 明确提示,不暴露细节

## 10. 测试策略

- **core 单测(Vitest)**:洗牌均匀性(统计分布)、抽牌不重复、正逆位概率(神谕卡断言无逆位)、模板组合逻辑(含 domains 领域匹配与回退)、AI 失败回退逻辑
- **API 集成测试**:口令鉴权通过/拒绝、解读缓存命中、限流生效、历史读写隔离(访客 A 不可见访客 B)
- **页面与动画**:手动验收为主

## 11. 部署方案

1. 服务器 clone 仓库 → `npm install && npm run build`
2. Fastify 进程伺服 `dist/` 静态文件 + API
3. pm2 守护,`.env` 注入 `ACCESS_CODE` / `AI_API_KEY` / `AI_BASE_URL` / `AI_MODEL`
4. 预留:nginx 反代 + HTTPS 证书(后续可加,架构无冲突)
